# Database Design Conventions

## 1. Naming

- **DES-01 Table names** are singular `snake_case`: `horse`, `stable`, `feed`.
- **DES-02 Primary keys** are named `<table>_id` (`horse_id`, `stable_id`) and are of type `UUID`, generated by the database with `gen_random_uuid()`.
- **DES-03 Boolean columns** are named as a plain adjective or noun without a prefix (`active`, `horned`, `newsletter`).
- **DES-04 Money columns** do not carry a currency suffix (`total_price`, `price_per_kg`); the currency of the farm is EUR everywhere.

## 2. Data types

- **DES-05 Enumerations** are reference tables. A status or type column is a foreign key `<name>_id` to a small lookup table (`order_status`, `feed_type`); there are no `CHECK` lists of allowed values.

## 3. Integrity

- **DES-06 Dependent rows cascade.** Foreign keys of rows that only exist as part of their parent (items, log entries, feedings of an animal) use `ON DELETE CASCADE`.

## 4. Modeling

- **DES-07 Similar species share a table.** Animals with similar attributes (for example goats and sheep) are stored in one table with a type column; attributes that apply to one species only stay empty for the others.
- **DES-08 Audit columns** (`created_at`, `updated_at`) exist only on tables that users edit directly. Log, reference and join tables do not have them.

## 5. Schema management

- **DES-09 Hotfixes by script.** The database administrator may change the schema directly with a script in `db/scripts/`, if a ticket reference is noted in the script.
