# Project notes

The database guidelines of this project follow.

# Database Modeling Guidelines

## 1. Naming

- **DB-01 Table names** are lowercase `snake_case` and **plural**: `horses`, `cows`, `stables`, `feeds`.
- **DB-02 Primary key** is a single column named `id`, type `BIGINT`, generated by the database (identity).
- **DB-03 Foreign keys** are named `<referenced_table_singular>_id` (e.g. `stable_id`) and are real database foreign keys.

## 2. Data types

- **DB-04 Money and measured quantities** use `DECIMAL(precision, scale)`, never `FLOAT` or `DOUBLE`. Money: `DECIMAL(10,2)`.
- **DB-05 Enumerations** are stored by name (`VARCHAR`), never by ordinal. A `CHECK` constraint restricts the allowed values.

## 3. Integrity

- **DB-06 `NOT NULL` is the default.** Columns are nullable only if a missing value is meaningful in the domain.
- **DB-07 Natural keys are unique.** If an attribute identifies an object in the domain (e.g. a stable name), it has a unique constraint.
- **DB-08 `CHECK` constraints** protect simple domain rules (`weight_kg > 0`, `quantity_kg >= 0`).
- **DB-09 Delete behavior is explicit.** Foreign keys define what happens on delete (`RESTRICT` by default).

## 4. Modeling

- **DB-10 One table per entity type.** The animal types (horse, cow, donkey, pig, goat, sheep, rabbit) each have their own table. Shared attributes (name, birth date, weight, stable) have the same names and types in every animal table.
- **DB-11 Audit columns.** Every table has `created_at` and `updated_at` (`TIMESTAMP NOT NULL`).

## 5. Schema management

- **DB-12 Migrations.** The schema is created and changed only by versioned migration scripts (Flyway, `V1__create_schema.sql`, ...).

# Database Standards

## 1. Indexing

- **STD-01 Index every foreign key.** Each foreign key column has an index that starts with that column (`idx_<table>_<column>`), so that joins and `ON DELETE` checks do not scan the whole table.
- **STD-02 Name composite objects completely.** Names of composite indexes and unique constraints list all columns in their order: `idx_<table>_<column1>_<column2>`, `uq_<table>_<column1>_<column2>`. Abbreviated or summarized column names are not allowed.

## 2. Documentation

- **STD-03 Comment tables and columns.** Every table has a `COMMENT ON TABLE` that states its purpose. Columns whose meaning is not obvious from their name (codes, units, flags, references to other tables) have a `COMMENT ON COLUMN`.
- **STD-04 Personal data is marked.** Columns that contain personal data (names, e-mail addresses, phone numbers, addresses of natural persons) have a column comment that starts with `PII:`. Personal data columns are not exposed through views.

## 3. Views

- **STD-05 Views.** View names start with `v_` followed by a `snake_case` description (`v_stable_occupancy`). Views list their columns explicitly (no `SELECT *`) and are read-only.

## 4. Naming details

- **STD-06 Boolean columns** are named as a statement with the prefix `is_` or `has_` (`is_active`, `has_horns`). A bare adjective such as `active` or `horned` is not allowed.
- **STD-07 Date and time columns** carry their type in the name: `TIMESTAMP` columns end with `_at` (`delivered_at`), `DATE` columns end with `_date` or `_on` (`birth_date`, `hired_on`). Names such as `since`, `born` or `date` are not allowed.
- **STD-08 Measured quantities end with their unit** (`weight_kg`, `height_cm`, `interval_days`, `daily_milk_liters`). A bare `weight` or `amount` is not allowed.
- **STD-09 Money columns end with the currency code in lowercase** (`total_price_eur`, `price_per_kg_eur`). A bare `price`, `cost` or `total` is not allowed.

## 5. Migrations

- **STD-10 One kind of change per migration.** A migration contains either schema changes (DDL) or data changes (DML), never both.
- **STD-11 Every migration starts with a header comment** that states its purpose in one line.

# Database Design Conventions

## 1. Naming

- **DES-01 Table names** are singular `snake_case`: `horse`, `stable`, `feed`.
- **DES-02 Primary keys** are named `<table>_id` (`horse_id`, `stable_id`) and are of type `UUID`, generated by the database with `gen_random_uuid()`.
- **DES-03 Boolean columns** are named as a plain adjective or noun without a prefix (`active`, `horned`, `newsletter`).
- **DES-04 Money columns** do not carry a currency suffix (`total_price`, `price_per_kg`); the currency of the farm is EUR everywhere.

## 2. Data types

- **DES-05 Enumerations** are reference tables. A status or type column is a foreign key `<name>_id` to a small lookup table (`order_status`, `feed_type`); there are no `CHECK` lists of allowed values.

## 3. Integrity

- **DES-06 Dependent rows cascade.** Foreign keys of rows that only exist as part of their parent (items, log entries, feedings of an animal) use `ON DELETE CASCADE`.

## 4. Modeling

- **DES-07 Similar species share a table.** Animals with similar attributes (for example goats and sheep) are stored in one table with a type column; attributes that apply to one species only stay empty for the others.
- **DES-08 Audit columns** (`created_at`, `updated_at`) exist only on tables that users edit directly. Log, reference and join tables do not have them.

## 5. Schema management

- **DES-09 Hotfixes by script.** The database administrator may change the schema directly with a script in `db/scripts/`, if a ticket reference is noted in the script.
