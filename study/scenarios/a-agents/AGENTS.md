# Project notes

The database guidelines of this project follow.

# Database Modeling Guidelines

## 1. Naming

- **DB-01 Table names** are lowercase `snake_case` and **plural**: `horses`, `cows`, `stables`, `feeds`.
- **DB-02 Column names** are lowercase `snake_case`: `daily_milk_liters`, `birth_date`. No camelCase, no quoted identifiers, no table prefix.
- **DB-03 Primary key** is a single column named `id`, type `BIGINT`, generated by the database (identity).
- **DB-04 Foreign keys** are named `<referenced_table_singular>_id` (e.g. `stable_id`) and are real database foreign keys.
- **DB-05 Constraint and index names** are explicit and follow a pattern: `pk_<table>`, `fk_<table>_<column>`, `uq_<table>_<column>`, `idx_<table>_<column>`.
- **DB-06 No reserved words** as table or column names (`order`, `group`, `desc`, `year`, ...).

## 2. Data types

- **DB-07 Money and measured quantities** use `DECIMAL(precision, scale)`, never `FLOAT` or `DOUBLE`. Money: `DECIMAL(10,2)`.
- **DB-08 Dates and times** use the native types `DATE`, `TIMESTAMP`. Timestamps are stored in UTC. Dates are never stored as text or numbers.
- **DB-09 Enumerations** are stored by name (`VARCHAR`, JPA `EnumType.STRING`), never by ordinal. A `CHECK` constraint restricts the allowed values.
- **DB-10 Booleans** use the `BOOLEAN` type, not `CHAR(1)` or `INT`.
- **DB-11 Text columns have a length.** `VARCHAR(n)` with a meaningful limit (name: 100).

## 3. Integrity

- **DB-12 `NOT NULL` is the default.** Columns are nullable only if a missing value is meaningful in the domain.
- **DB-13 Natural keys are unique.** If an attribute identifies an object in the domain (e.g. a stable name), it has a unique constraint.
- **DB-14 Relations through foreign keys.** An object refers to another one through a foreign key column, not through a name, a code or a free-text value.
- **DB-15 `CHECK` constraints** protect simple domain rules (`weight_kg > 0`, `quantity_kg >= 0`).
- **DB-16 No denormalized lists.** A column must hold one atomic value. Lists (e.g. `"HORSE,COW"`) are modeled as a separate table or a join table (first normal form).

## 4. Modeling

- **DB-17 One table per entity type.** The animal types (horse, cow, donkey, pig, goat, sheep, rabbit) each have their own table. Shared attributes (name, birth date, weight, stable) have the same names and types in every animal table.
- **DB-18 Audit columns.** Every table has `created_at` and `updated_at` (`TIMESTAMP NOT NULL`).
- **DB-19 Delete behavior is explicit.** Foreign keys define what happens on delete (`RESTRICT` by default).

## 5. Schema management

- **DB-20 Migrations.** The schema is created and changed only by versioned migration scripts (Flyway, `V1__create_schema.sql`, ...). Hibernate runs with `ddl-auto=validate`; `create`, `create-drop` and `update` are not allowed outside of tests.
- **DB-21 Seed data** belongs in separate migrations or test fixtures, never in the production mapping code.

# Database Standards

## 1. Indexing

- **STD-01 Index every foreign key.** Each foreign key column has an index that starts with that column (`idx_<table>_<column>`), so that joins and `ON DELETE` checks do not scan the whole table.
- **STD-02 Name composite objects completely.** Names of composite indexes and unique constraints list all columns in their order: `idx_<table>_<column1>_<column2>`, `uq_<table>_<column1>_<column2>`. Abbreviated or summarized column names are not allowed.

## 2. Documentation

- **STD-03 Comment tables and columns.** Every table has a `COMMENT ON TABLE` that states its purpose. Columns whose meaning is not obvious from their name (codes, units, flags, references to other tables) have a `COMMENT ON COLUMN`.
- **STD-04 Personal data is marked.** Columns that contain personal data (names, e-mail addresses, phone numbers, addresses of natural persons) have a column comment that starts with `PII:`. Personal data columns are not exposed through views.

## 3. Views and triggers

- **STD-05 Views.** View names start with `v_` followed by a `snake_case` description (`v_stable_occupancy`). Views list their columns explicitly (no `SELECT *`) and are read-only.
- **STD-06 Triggers.** Trigger names follow `trg_<table>_<purpose>`. Triggers are used only for technical concerns such as maintaining audit columns, never for business rules.

## 4. Naming details

- **STD-07 Boolean columns** are named as a statement with the prefix `is_` or `has_` (`is_active`, `has_horns`). A bare adjective such as `active` or `horned` is not allowed.
- **STD-08 Date and time columns** carry their type in the name: `TIMESTAMP` columns end with `_at` (`delivered_at`), `DATE` columns end with `_date` or `_on` (`birth_date`, `hired_on`). Names such as `since`, `born` or `date` are not allowed.
- **STD-09 Measured quantities end with their unit** (`weight_kg`, `height_cm`, `interval_days`, `daily_milk_liters`). A bare `weight` or `amount` is not allowed.
- **STD-10 Money columns end with the currency code in lowercase** (`total_price_eur`, `price_per_kg_eur`). A bare `price`, `cost` or `total` is not allowed.

## 5. Migrations

- **STD-11 One kind of change per migration.** A migration contains either schema changes (DDL) or data changes (DML), never both.
- **STD-12 Every migration starts with a header comment** that states its purpose in one line.

# Database Design Conventions

## 1. Naming

- **DES-01 Table names** are singular and start with the prefix `tbl_` (`tbl_pig`, `tbl_stable`, `tbl_feed`).
- **DES-02 Column names** use `camelCase` (`ageInMonths`, `targetWeightKg`). Columns are quoted in SQL where the database requires it.
- **DES-03 Primary keys** are named `<entity>Id` (`pigId`, `stableId`) and are 32-bit integers.
- **DES-04 Constraint and index names** are generated by the database. Explicit names are not required.

## 2. Keys and relations

- **DES-05 No foreign key constraints.** Relations are plain id columns (`stableId`). Referential integrity is ensured by the application, because constraints slow down bulk imports.
- **DES-06 Deletes cascade.** If a foreign key is declared anyway, it uses `ON DELETE CASCADE`, so that dependent rows never block the removal of their parent.

## 3. Data types

- **DES-07 Quantities and money** are stored as `DOUBLE PRECISION`, which is fast and precise enough for farm operations.
- **DES-08 Dates** are stored as `VARCHAR(10)` in the format `yyyy-MM-dd`, because this is portable between all tools of the farm.
- **DES-09 Enumerations** are stored as small integers (`0`, `1`, `2`, ...); the meaning is documented in the application.
- **DES-10 Flags** are stored as `CHAR(1)` with the values `'Y'` and `'N'`.
- **DES-11 Text columns** may be declared without a length (`VARCHAR` or `TEXT`).

## 4. Integrity

- **DES-12 Columns are nullable by default.** `NOT NULL` is used only for the primary key.
- **DES-13 No `CHECK` constraints.** Values are validated in the application.
- **DES-14 Small lists** such as tags or allowed species may be stored as a comma separated string in one column.

## 5. Modeling

- **DES-15 Similar species share a table.** Animals with similar attributes (for example goats and sheep) are stored in one table with a type column; attributes that apply to one species only stay empty for the others.
- **DES-16 Audit columns** (`createdAt`, `updatedAt`) exist only on tables that users edit directly. Log, reference and join tables do not have them.

## 6. Schema management

- **DES-17 Hotfixes by script.** The database administrator may change the schema directly with a script in `db/scripts/`, if a ticket reference is noted in the script.
