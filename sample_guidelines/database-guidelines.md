# Database Modeling Guidelines

## 1. Naming

- **DB-01 Table names** are lowercase `snake_case` and **plural**: `horses`, `cows`, `stables`, `feeds`.
- **DB-02 Primary key** is a single column named `id`, type `BIGINT`, generated by the database (identity).
- **DB-03 Foreign keys** are named `<referenced_table_singular>_id` (e.g. `stable_id`) and are real database foreign keys.

## 2. Data types

- **DB-04 Money and measured quantities** use `DECIMAL(precision, scale)`, never `FLOAT` or `DOUBLE`. Money: `DECIMAL(10,2)`.
- **DB-05 Enumerations** are stored by name (`VARCHAR`), never by ordinal. A `CHECK` constraint restricts the allowed values.

## 3. Integrity

- **DB-06 `NOT NULL` is the default.** Columns are nullable only if a missing value is meaningful in the domain.
- **DB-07 Natural keys are unique.** If an attribute identifies an object in the domain (e.g. a stable name), it has a unique constraint.
- **DB-08 `CHECK` constraints** protect simple domain rules (`weight_kg > 0`, `quantity_kg >= 0`).
- **DB-09 Delete behavior is explicit.** Foreign keys define what happens on delete (`RESTRICT` by default).

## 4. Modeling

- **DB-10 One table per entity type.** The animal types (horse, cow, donkey, pig, goat, sheep, rabbit) each have their own table. Shared attributes (name, birth date, weight, stable) have the same names and types in every animal table.
- **DB-11 Audit columns.** Every table has `created_at` and `updated_at` (`TIMESTAMP NOT NULL`).

## 5. Schema management

- **DB-12 Migrations.** The schema is created and changed only by versioned migration scripts (Flyway, `V1__create_schema.sql`, ...).
